# 把电脑上的 Claude Code 接到手机里

一句话：电脑上跑一个小服务，把 Claude Code 装成一个普通的 OpenAI 接口，
手机上的栖当成又一个供应商用。同一个 WiFi 下直接连，**不用 Tailscale**
（你说 Tailscale 跟梯子打架，那就不碰它）。

---

## 一次性：先确认 claude 能用

在电脑上开一个终端，挂着你平时用的梯子，跑：

```
claude -p "说一个字：好"
```

- 打出「好」→ 成了，往下走。
- 打出 **Not logged in** → 先 `claude` 登录一次，登好了再回来。

桥本身不管登录这件事，它只是替你按回车。

⚠️ **在别的地方看到「Not logged in」不一定是真的没登录**：
读不到钥匙串（比如在沙箱、在另一个用户下跑）也是这句话。
以 `claude` 启动时那块横幅为准——上面写着你的账号就是登着的。

## ⚠️ 先解决一件事：**终端要走代理**

（2026-08-23 实测踩到的。）

登录报 `OAuth error: connect ECONNREFUSED 31.13.94.41:443`，retry 多少次都一样——
**31.13.x.x 是 Meta 的 IP 段**，说明 `platform.claude.com` 在终端那边
被解析到了完全不相干的地址上。

症状很好认：**浏览器能打开授权页，终端连不上。**
因为大多数梯子只设「系统代理」，而 Node／终端程序不一定读它。

两个办法：

**① 这一次让终端走代理**（试一次就知道行不行）

```
set HTTPS_PROXY=http://127.0.0.1:7890
set HTTP_PROXY=http://127.0.0.1:7890
claude
```

端口换成你梯子的：Clash 一般 7890，v2rayN 一般 10809。
三条要在**同一个终端窗口**里依次跑。

**② 开梯子的 TUN / 虚拟网卡模式**（一劳永逸）

开了之后所有程序都走代理，终端也不例外，以后不用每次设。

⚠️ **桥 spawn 出来的 claude 会继承起桥那个终端的环境变量。**
所以用办法 ① 的话，**必须在设过 `HTTPS_PROXY` 的那个窗口里起桥**，
不然桥里的 claude 一样连不上。用 ② 就没这个问题。

## 每次要用：起桥

在终端里跑：

```
node "D:\OneDrive\桌面\qi-nativev65\scripts\claude-bridge\bridge.js"
```

（同目录下有个 **启动桥.bat** 可以双击——但如果 `.bat` 的默认打开方式
被改成过 VSCode，双击会变成「用编辑器打开这个文件」。
修：右键那个 bat → 打开方式 → 选「Windows 命令处理程序」→ 勾「始终使用」。）

窗口里会打出这么一行：

```
接口地址   http://192.168.124.11:8787/v1
```

**记下那个地址**，每次连不同 WiFi 数字可能会变。

## 手机上：加一个供应商

设置 → 供应商 → 新增：

| 填什么 | 填成 |
|---|---|
| 接口地址 | 窗口里打出来的那个 `http://192.168.x.x:8787/v1` |
| 模型 | **`sonnet`**（见下面那条） |
| 密钥 | 留空 |

要给它上把锁的话，起桥之前先设 `BRIDGE_TOKEN`，手机那边的密钥栏填一样的字。

⚠️ **模型填 `sonnet`。** 2026-08-23 登录成功之后横幅上写的是
`Sonnet 5 · Claude Pro`——Pro 这一档主力是 Sonnet，
填 `opus` 大概率会被拒或者悄悄降级。想确认现在能用哪个，
在电脑上 `claude` 里敲 `/model` 看一眼。

⚠️ **桥花的是你自己的订阅额度。** 用它聊天会挤占你在电脑上用 Claude Code 的额度
（Pro 是按时间窗口算的）。这跟 API 计费那条路是两笔钱，别搞混。

## 说清楚这座桥做不到什么

**一、电脑关了就没了。** 桥跑在电脑上，电脑睡了、WiFi 断了、那个黑窗口关了，
手机上这个供应商就连不上。切回原来的供应商还是能聊——不会把你锁在外面。

**二、工具是「用文字约的」，不是真的函数调用。**
Claude Code 那头只会说话，不认工具协议。所以桥把工具清单写进系统提示，
让他要用工具的时候只输出一段固定格式的 JSON，桥再翻译回 App 认的格式。
**他偶尔会不照格式写**——那一轮就当普通说话，不会崩，只是那次没调成。
真在意某个工具调得准不准，用原来的供应商更稳。

**三、图是走「路径」给他的。**
你发的图会先落到电脑的临时目录，把路径告诉他，他用自己的 Read 工具去看。
所以带图那一轮会慢一点。看完就删。

**四、每轮都是从头讲一遍。**
桥不留会话，每次都把整段历史重新递过去——跟 App 原来对着 API 说话是一样的，
只是这一份走的是你的 Claude Code 额度。

## 拧螺丝的地方（都是环境变量，不改也能用）

| 名字 | 默认 | 干嘛的 |
|---|---|---|
| `BRIDGE_PORT` | 8787 | 换个端口 |
| `BRIDGE_TOKEN` | 空 | 给桥上锁，手机那边密钥填一样的 |
| `BRIDGE_CONCURRENCY` | 3 | 同时最多跑几个 claude |
| `BRIDGE_TIMEOUT` | 280000 | 一轮最多等多少毫秒 |
| `BRIDGE_CLAUDE` | 自动找 | claude 本体的路径，自动找不着的时候手填 |

## 连不上的时候，按顺序试

1. 电脑上开浏览器进 `http://127.0.0.1:8787/` —— 打出「桥是通的」就说明服务没问题。
2. 手机浏览器进 `http://192.168.x.x:8787/` —— 打不开就是 WiFi/防火墙的事：
   Windows 第一次会弹一个「允许 Node.js 通过防火墙」，**要点允许，而且要勾上专用网络**。
3. 两台确认在同一个 WiFi 上（手机别挂着流量）。
4. 黑窗口里会打出每一轮的日志（几条消息、几张图、花了几秒、报了什么错），
   出问题先看那儿。
